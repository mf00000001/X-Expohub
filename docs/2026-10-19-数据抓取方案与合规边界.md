# 展会信息公开采集方案与合规边界（2026-10-19 决策）

> 决策来源：0930 建议（沈）第 2 条「增加绕过举办方的数据抓取」，用户于 2026-10-19 确认执行，方式为**后续新增脚本抓取**。
> 本文是执行前的方案与红线；代码骨架见 `scripts/scrape/`，**默认不联网、不落库**。

---

## 1. 要解决什么

平台不再依赖举办方开放数据（主办方角色已于 2026-10-19 取消，展会改平台自营）。冷启动需要自己攒展会目录，因此需要从**公开可访问**的渠道采集：

- 展会名称、起止时间、城市/展馆、公开简介、公开封面图
- 来源链接（可追溯、可撤下）

**不采集**：联系人姓名、手机号、邮箱、微信、名片信息、观众/参展商名录、任何需要登录或付费才能看到的数据。

## 2. 合规边界（硬性，代码里已落为默认拒绝）

| 约束 | 依据 | 代码/流程落点 |
|---|---|---|
| 只抓公开页面，遵守 `robots.txt` | 《网络安全法》《数据安全法》基本要求；站点服务条款 | `RobotsCache.allowed()`：取不到 robots.txt 时**默认不允许**；被 Disallow 的来源直接跳过，**不提供绕过开关** |
| 不采集个人信息 | 《个人信息保护法》第 6/13/17 条（最小必要、告知同意） | 字段白名单 `FIELD_WHITELIST`；命中 `phone/email/contact/微信/姓名…` 的字段**直接丢弃并打印**（`sanitize()`） |
| 不把联系人用于营销触达 | 合规篇 01 的结论（P0-2）：登记过 ≠ 同意新平台推广 | 采集层就不落联系方式，后续无触达链路 |
| 控制抓取强度 | 避免干扰对方站点/构成不当竞争 | `delay_seconds`、`max_pages`、超时；单来源串行 |
| 不用抓来的数据做模型训练 | 《生成式人工智能服务管理暂行办法》第 7 条 | 采集产物只进「展会目录」，不进食材/文档语料 |
| 来源可追溯、可下架 | 广告法真实性 + 权利人异议处理 | 每条带 `source_url / source_name / fetched_at`；导入前人工复核 |
| 不污染既有数据 | 现有库里有 `test`、`日期 0123-12-03` 等脏数据 | `sanitize()` 校验日期区间（2000–2100），非法直接丢；导入接口按标题去重 |

> 结论：**能抓的是「展会事实」，不能抓「人」**。这也是 01/02 两篇合规文档给出的唯一可行切法。

## 3. 技术方案（四段式，可审计）

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌────────────────────┐
│ 采集适配器    │→ │ 规范化/白名单 │→ │ 去重+人工复核 │→ │ 平台批量导入 API    │
│ (每站一个)    │   │ + 日期校验    │   │ JSON 产物    │   │ /platform/import/…  │
└──────────────┘   └──────────────┘   └──────────────┘   └────────────────────┘
   robots 检查         联系方式剥离        (title,star_date)     标题去重 + 逐行校验
   限速/超时           字段白名单          重复丢弃              status=draft 待发布
```

### 3.1 为什么复用导入接口，而不是直接写库

- 已有 `POST /api/platform/import/exhibitions`：**标题去重、逐行校验、失败行不阻断**，且 2026-10-19 起导入即归「平台运营」（`organizer_name=平台运营`）。
- 采集器不持有数据库写权限，只产出 JSON → 审计链清晰（谁抓的、什么时候、从哪抓的都在 JSON 里）。

### 3.3 运行方式

```bash
# 离线自测（不联网）
python scripts/scrape/expo_scraper.py \
  --fixture docs/evidence/scrape_fixture.json --out out/demo.json

# 真实抓取（需 sources.json 里 enabled=true，并显式允许联网）
python scripts/scrape/expo_scraper.py --allow-network --out out/exhibitions.json

# 人工复核后推送（管理员 token）
python scripts/scrape/expo_scraper.py --push out/exhibitions.json \
  --api http://127.0.0.1:8002 --token <admin_access_token> --status draft
```

## 4. 待你确认（不确认不抓真站）

1. **来源清单**：具体哪些网站？（广交会/进博会/高交会官网？行业协会站？聚合平台？）
2. **授权情况**：是否有书面许可/合作意向？没有的话只能抓公开页且严格限制字段与频次。
3. **频率与量级**：每日/每周？单次上限多少条？
4. **是否要落「来源」字段到库**：当前 `exhibitions` 表无 `source_url` 列，来源信息只留在 JSON。若要长期可追溯，需加列（`source_url`、`fetched_at`、`license_note`）。
5. **谁能发布**：采集进来默认 `draft`，需人工复核后 `published` —— 复核由谁做？

## 5. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 站点改版 | 适配器失效 | 每个来源独立 parser，失败只影响该来源 |
| 反爬/封禁 | 触发风控 | 限速 + 低频 + 只抓列表页 |
| 数据错误 | 日期/地点写错 → 用户投诉 | 日期校验 + 人工复核 + 入库后可在后台编辑 |
| 法律风险 | 抓取他人站点数据、使用展会名称/图片 | 只抓事实性字段（名称/时间/地点），图片只用官方公开封面或改用自生成封面（仓库已有 `scripts/gen_expo_covers.py`） |
| 与举办方关系 | 「绕过举办方」若被解读为搭便车 | 对外定位：**平台自营的展会目录**，只做信息展示与撮合，不冒充举办方 |
