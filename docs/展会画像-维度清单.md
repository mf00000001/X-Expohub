# 展会画像维度清单

> 目的：为 ExpoHub 的"展会 ↔ 展商 / 采购商"匹配提供前置条件。
> 版本：**v0.4**（2026-11-02）。v0.1 只有"展会侧"；v0.2 依据《展会决策打分表-金标准采集 v2》（牛强，2026-10-26）补上"我方侧"，并吸收其标注方法论；v0.3 新增第 9 节"能拆成多少张画像"；v0.4 新增第 10 节"展商侧 E1–E6 的实现"。

---

## 0. 参考表校准了什么（先说结论）

那张《展会决策打分表》**不是画像字段表，是标注工具**。它采的不是数据，是"人对某个具体企业、这些展值不值得去"的判断，用途是校准权重和定义验收口径。

这个定位很重要，因为它决定了：**其中关于"怎么采"的部分可以直接搬，关于"采什么"的部分只能部分搬。**

它做对的（详见第 6 节）：
1. 把展商和采购商拆成两张独立表，字段都不同（采购商没有展位费列）
2. 用**虚构参照画像**（代工厂 / 品牌采购）锁死判断基准，禁止按自己公司判断
3. 给了**硬判据**：参展=找客户，到场主要是设备商/材料商/同行 → 0 分，哪怕它再大
4. 强制写理由，给了句式模板和反例（"挺好的""还行"会被退回）
5. 有**置信度**列，并要求"不确定就标低，不要留空"
6. 让填表人自陈"哪一列最难填、为什么"
7. 有权重直觉采集（1~9 分 + 排序 + 理由），且留了自由补充因子的空行
8. 有一致性核算（Fleiss' κ ≥0.6 可用 / ≥0.8 良好），并把"分歧最大的 5 个展"当成资产
9. 明确声明规模边界：120 条只够拟合 5 个权重，不足以训练模型

它做错的（详见第 7 节）：
1. 30 个展里 23 个是毫不相干的行业，导致 23 条标注全部落在 0 分——**不是人没区分度，是样本没区分度**
2. 意愿只有 4 档，且把"想不想去"和"能不能去"混在一起
3. 05 定义的 C1–C7 与 02 表里实际用的编号对不上（编码错位）
4. 采购商侧完全没有成本维度
5. 驱动因素强制单选

## 1. 核心修正：画像必须三分，不是一个

v0.1 只画了"展会"。这是不够的——**"值不值得去"从来不是展会的属性，是"展会 × 我"的关系**。

| 画像 | 回答什么 | 谁提供 | 变化频率 |
|---|---|---|---|
| **展会画像** | 这个展本身是什么、里面是谁 | 平台采集/主办方录入 | 每届更新 |
| **展商自画像** | 我卖什么、卖给谁、预算多少 | 展商自己填 | 季度级 |
| **采购商自画像** | 我买什么、采购额多大、看重什么 | 采购商自己填 | 季度级 |
| **匹配结论** | 这个展对我的客户群覆盖多少 | 前两个导出，不单独采集 | 实时计算 |

同一场 AWE，对"能做小批量试单的代工厂"是 A 级，对"只接 10 万台起订的大厂"是 C 级。**展会画像再准，没有我方画像也判不出可去。**

> 参考表的 04 sheet 就是在做这件事，而且做得很实：它把"单次参展预算 ≤5 万、一年只够认真参加 2~3 个展"写成硬约束。这一条比任何评分权重都更能改变结论——**预算约束下的选择，才是真决策**。

## 2. 第一画像：展会侧（六层，v0.1 保留）

从"能不能去"到"值不值得去"，逐层收窄。**L0 是过滤，不打分；L1–L5 才进加权。**

- **L0 硬门槛** —— 不满足直接排除
- **L1 基本盘** —— 这是个什么展会
- **L2 供需结构** —— 谁在里面（匹配的核心前置）
- **L3 商业价值** —— 划不划算
- **L4 体验与风险** —— 去了能不能顺利落地
- **L5 时效与稀缺** —— 现在该不该动

**数据可得性标记：** `A` 平台自有行为数据 ｜ `B` 主办方填写（需审核） ｜ `C` 公开可爬 ｜ `D` 需第三方 ｜ `E` 通常拿不到

### L0 硬门槛（过滤，不评分）

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| 举办确定性 | 已确认 / 预告待确认 / 有延期取消史 | 高 | 高 | C |
| 举办时间 | 起止日期、与用户档期是否冲突 | 高 | 高 | A |
| 报名/展位截止 | 展位申请截止、观众预登记截止 | 高 | 中 | B/C |
| 地理可达 | 国家-城市-场馆；跨境签证难度 | 中 | 高 | C+D |
| **观众准入类型** | 专业观众 only / 公众开放 / 混合 | 高 | **极高** | C |
| 参展资格限制 | 是否限制同类竞品、区域独家 | 高 | — | B |
| **品类是否命中** | 展会主品类 ∩ 用户关注品类 ≠ ∅ | 极高 | 极高 | A |

**参考表补的一条更锐利的判据**（建议直接写进 L0）：

> **到场结构判断**：到场的人里，买方 / 卖方 / 同行 / 上游供应商 各占多少？
> 参展视角下，"到场主要是设备商、材料商、同行"→ 直接出局，**哪怕它是行业第一大展**。
> 表里点名的三个反例很有说服力：CIMT 机床展（买机床的工厂+卖机床的厂商，没有买小家电的品牌商）、进博会（外国品牌商+进口商，成品不展工厂）、服贸会（服务商+投资机构）。

"品类命中"不够用，因为同一品类下买方和卖方会同时出现。**要看的是"到场者的角色构成"，不是"品类是否沾边"。**

### L1 基本盘

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| 展会性质 | B2B 专业展 / B2C 消费展 / 混合 | 高 | 极高 | C |
| 主办方画像 | 名称、性质（政府/协会/民营/外资）、办展年限 | 高 | 中 | C |
| 届次 | 第 N 届；第 1 届风险显著偏高 | 高 | 中 | C |
| 规模 | 展商数、净面积、观众数、展馆数 | 高 | 高 | C |
| 国际化程度 | 海外展商占比、海外观众占比 | 中 | 高 | C/D |
| 行业地位 | 是否该品类头部展 | 高 | 高 | C(推断) |
| 权威认证 | UFI、协会背书、政府支持 | 中 | 中 | C |

> 观众数口径极脏：有人报"人次"、有人报"注册数"、有人把直播观看算进去。**必须记录口径来源**，否则跨展不可比。

### L2 供需结构（最关键，匹配的直接前置）

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| **品类标签树** | 一级/二级/三级，受控词表，展会↔标签多对多+权重 | 极高 | 极高 | C |
| **品类分布** | 各品类展商数量及占比 | 高 | 极高 | C |
| **品类集中度** | Top1 占比 / HHI → 垂直专展 or 大杂烩 | 高 | 极高 | C(计算) |
| **展商名录结构** | 头部品牌数、新展商占比、**复展率** | 极高 | 高 | C/D |
| **观众身份构成** | 采购/技术/经销/终端/媒体/学生 占比 | **极高** | 中 | B/D |
| **观众职级分布** | 决策权/建议权/执行层 占比 | **极高** | 低 | B/D |
| 观众公司规模分布 | 大/中/小/个体 | 高 | 低 | D |
| 观众地域分布 | 本地/外地/海外 | 中 | 中 | D |
| 买家团/采购对接会 | 往届组团买家数、对接会规模 | 高 | 高 | B |
| **供需重合度** | 展会品类分布 vs 平台内采购需求分布的重合 | 高 | 高 | A(平台算) |

> **复展率是展览质量最硬的单一指标**，比任何宣传都可靠：70% 以上基本不会差，30% 以下要警惕。
> **品类标签必须是受控词表**。参考表里"行业大类"是自由文本（"综合/家电展区""礼品/家居""消费品"混着写），这类字段在匹配阶段等于零价值。

### L3 商业价值

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| **展位价格带** | 标摊价/光地价(元/㎡)/价格分位 | 极高 | — | C/B |
| 附加费用 | 搭建、水电、管理费、押金、指定搭建商 | 高 | — | B |
| **单位观众成本** | 展位总成本 ÷ 预计有效专业观众数 | 极高 | — | A(派生) |
| 线索效率 | 往届单展位平均有效线索数 | 极高 | — | E/B |
| 品牌曝光 | 行业媒体覆盖、同期论坛规格 | 中 | 低 | C |
| 成交属性 | "现场下单型"还是"形象展示型" | 高 | 中 | D |
| **采购商侧成本** | 差旅+门票+天数+机会成本 | — | **高** | A(自算) |

> 展商侧该给的不是"展位多少钱"，是**"每拿到一个有效线索花多少钱"**（参考表称之为 CPL，方向是对的）。
> 采购商侧的"没有成本维度"是个缺陷——"不付展位费"不等于没成本，差旅和时间才是他们的真实门槛。

### L4 体验与风险

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| 场馆硬件 | 面积、层高、承重、货运通道、网络 | 高 | 低 | C |
| 同期活动 | 论坛、新品发布、采购对接会 | 中 | 高 | C |
| 配套条件 | 酒店价格带、交通、餐饮 | 中 | 高 | C |
| 服务限制 | 指定搭建商、进场/撤展时间窗 | 高 | — | B |
| 风险记录 | 往届延期/取消/缩水、退费纠纷 | 高 | 中 | C/D |
| **往届口碑** | 展商/观众评分 + 评价文本 | 极高 | 高 | A |

### L5 时效与稀缺

| 字段 | 说明 | 展商 | 采购商 | 可得性 |
|---|---|---|---|---|
| 展位余量 | 剩余数 / 售罄速度 | 高 | — | B/A |
| 早鸟价窗口 | 早鸟截止、阶梯价 | 高 | — | B |
| 热度曲线 | 报名展商名单增长速度 | 中 | 中 | C(派生) |
| **档期冲突** | 与已有行程、同期同类展撞车 | **极高** | 高 | A |

> 参考表完全没有"举办月份"这个字段。对预算只够参加 2~3 个展的企业，**档期冲突和价格一样是硬约束**，漏掉它会让推荐结果无法执行。

## 3. 第二画像：展商自己（v0.2 新增）

字段直接借鉴参考表 04-A，并补三项。**这些字段决定同一展对不同企业的结论分歧。**

| 字段 | 参考表原字段 | 为什么它改变结论 |
|---|---|---|
| 卖什么（品类+工艺能力） | ① 我卖什么 | 决定"对口"的边界。整机代工 ≠ 零部件供应 |
| 卖给谁（客户类型） | ② 我卖给谁 | 决定要判断"到场的是不是这类人" |
| 目标客户在展会上是谁 | ③ 谁会出现在展会上 | 把"客户类型"翻译成"可识别的到场角色" |
| 企业规模 | 企业规模 | 影响买家对你验厂/产能的信心 |
| 竞争优势 | 竞争优势 | 决定你在同质化展会里能否被看见 |
| **单次参展预算** | 单次参展预算 | **硬约束**。≤5 万意味着一届只能去 2~3 个 |
| **参展目标权重** | 参展主要目标（8 成订单+2 成曝光） | 目标不同 → 评分权重不同 |
| 主要客户区域 | 主要客户区域 | 决定地域类展会的价值 |
| **产能与最小起订量** | （新增） | 能不能接小单，直接决定 AWE 这类"只谈大单"的展值不值得去 |
| **资质与认证** | （新增） | 有些展的买家有硬性验厂/认证门槛 |
| **历史参展复盘** | （新增） | 上届来了多少线索、成交几单。**没有这一项，所有判断都只是预判** |

## 4. 第三画像：采购商自己（v0.2 新增）

| 字段 | 参考表原字段 | 为什么它改变结论 |
|---|---|---|
| 买什么（品类清单） | ① 我要买什么 | 决定要找哪几类供应商 |
| 卖给谁（渠道） | ② 我卖给谁 | 影响对供应商能力的要求 |

## 5. 匹配结论：三段式，不给单一总分

```
① 硬门槛过滤 → 输出"排除项 + 原因"
② 分角色加权打分 → 0~100，权重按角色不同
③ 输出 3~5 条可解释理由 + 1~2 条明确的不匹配信号
```

**展商侧（ROI 不等式）：**
```
预期有效线索数 × 客单价 × 成交率 > 展位 + 搭建 + 差旅 + 人力 + 机会成本
```
系统负责估左边第一项；右边让用户填。**先做"帮用户算右边 + 估左边"，比给一个总分有用得多。**

**采购商侧（效率比较）：**
```
本展覆盖的「我的目标品类」供应商数 ÷ 到场时间成本  vs  线上找/直接拜访的同等成本
```
硬约束：**目标品类展商数 < 5 家 → 直接提示"不建议专程前往"**。

## 6. 采集方法论（参考表最值钱的部分，建议整段搬走）

这一节与"字段"无关，是"怎么拿到可信的判断"。参考表在这里做得非常专业：

| 机制 | 具体做法 | 为什么有效 |
|---|---|---|
| **参照画像锁基准** | 定义虚构企业 A/B，强制"只按画像判断，不按自己公司" | 否则每个人按自己经验判，分数不可比 |
| **置信度** | 高/中/低，且"不确定就标低，不要留空，记不准本身是有效信息" | 把认知不确定性显式化，比假装知道有价值 |
| **理由模板** | 三种句式：对口/不对口/大展陷阱；反例："挺好的""还行""少于 15 字"退回 | 强制回答"谁会在场 + 为什么对口" |
| **一致性检验** | Fleiss' κ ≥0.6 可用 / ≥0.8 良好；分歧最大的 5 个展写进规范 | 把标注分歧当资产，不是噪声 |
| **权重直觉采集** | 1~9 分 + 排序 + 理由，留自由补充行 | 不预设权重，且承认因子可能不全 |
| **元数据自陈** | "哪一列最难填？为什么？" | 直接暴露哪些字段采不到 |
| **边界声明** | "120 条只够拟合 5 个权重，不足以训练模型" | 避免用错工具 |
| **自检分布** | 期望 3 分 3~6 个、2 分 4~8 个、1 分 5~10 个、0 分 10~15 个 | 发现"没区分"的机械检查 |

> 参考表里填表人自己写的"哪一列最难填"，是全表最有价值的一条元数据：
> **「对口采购商数量级」——没数据，只能凭印象估计，同时无法判断展会大而全自己是否有竞争优势。**
> 这句话直接告诉我们：L2 的"观众构成/采购商数量"在现实中采不到，只能靠印象分级。平台的差异化机会就在这里——**把这列从"印象"变成"可核查"**。

## 7. 不要照搬的（糟粕清单）

| # | 问题 | 后果 | 怎么改 |
|---|---|---|---|
| 1 | **样本全在决策边界之外**：30 个展里 23 个是机床/医疗/纺织/家具/五金/汽车/安防/印刷/宠物/美妆/光伏/教育/农业/物流/建材/服装/口腔/石油 | 任何人都会打 0 分，23 条标注白费，有效样本只剩 7×4=28 条。作者误诊为"我没区分度"，实际是"样本没区分度" | **在边界取样**：母婴、宠物用品、酒店用品、烘焙、咖啡、便利店、家居、户外露营、茶饮设备——这些才是真正需要判断的。标注预算要花在模型最容易错的地方 |
| 2 | 意愿只有 4 档，且"一定会去/比较想去/可能会去"混了意愿与能力 | 4 档只能做分类，做不了回归；"想去但没钱"和"不想去"被合并 | 改采两个量：**给定预算下买不买**（是/否）+ **愿意出的最高价**（连续值）。信息量大一个量级 |
| 3 | **编码表错位**：05 定义 C1 对口客户多 / C2 性价比 / C4 社会辐射，而 02 表实际用了 C1 对口展商多 / C2 品类齐全 / C4 新品与趋势 | 两张表的编码不同源，后续统计直接失效。表里自己写了"不要改下拉选项否则程序读不了" | 编码表独立成一个受控维度，两表共用，且做**导入时校验**（非法编码拒收） |
| 4 | 采购商侧完全没有成本维度（"不付展位费，敏感度低"） | 差旅和时间才是采购商的真实门槛，漏掉就无法解释"为什么这个展他不去" | 补差旅成本、可接受半径、天数预算 |
| 5 | 驱动因素**强制单选** | 真实决策是"对口 **且** 近 **且** 便宜"，单选会系统性高估单一因子 | 允许"主因 + 次因"，或改成多选+权重 |
| 6 | 缺举办月份 / 档期 | 预算只够 2~3 个展时，撞期是硬约束 | L5 必须有档期冲突 |
| 7 | 只有预判，没有复盘 | 决策闭环缺一半，权重永远校准不准 | 补"上届实际：线索数 / 成交数 / 花费" |
| 8 | 基础字段就有"待核实"（城市列 6 个待核实） | 身份信息未坐实就打主观分，顺序反了 | 先结构化 L0/L1，再做判断 |
| 9 | 权重因子全是"展会怎么样"，没有一条"我怎么样" | 同一展对不同企业结论相反，但因子表无法表达这种分歧 | 权重表要按"我方画像类型"分组，不是全体共用一套 |

## 8. 落地到本项目

现有 `Exhibition` 表只有：名称、日期、场馆、城市、展位数、观众数。

| 优先级 | 需要补的 | 归属 |
|---|---|---|
| P0 | 品类标签树（受控词表，多对多+权重） | 新表 `tags` + `exhibition_tags` |

| P1 | 展位价格带、面积、附加费用 | 新表 `exhibition_pricing` |

| P2 | 口碑评分与评价 | 复用 `Review` 表扩展 |
| P2 | 同期活动、场馆硬件、服务限制 | JSON 扩展字段 |

## 9. 一个展会能拆成多少张画像

### 9.1 先定规则，否则数字没有意义

**一张画像 =（受众角色，决策问题，字段集）。** 三者中"字段集"不同才算新画像；只有措辞不同、字段完全相同的，是同一张画像的两种解读（derived view），不是两张。

按这个规则，41 个展会字段先聚成 **10 个角色无关的原子块**：
时间与确定性 / 品类结构 / 到场者结构 / 展商构成 / 价格与成本 / 交易成果 / 权威与声量 / 运营与体验 / 风险与口碑 / 时效与稀缺

### 9.2 三个数字

| 口径 | 数量 | 怎么来的 | 该不该做 |
|---|---|---|---|
| **字面穷举** | ≈96 | 12 张 × 4 决策场景 × 2 粒度（品类级/单品级） | 不该。其中 84 张是同一份字段换输出形态 |
| **结构上限** | **12** | 10 个原子块按角色口径分叉，去掉单侧无意义的 | 上限。再多必然字段重复 |
| **v1 建议** | 6 | 12 张里只保留数据能撑住的 | 先做 |

若允许按届次做时间切片、按品类做切片，数量可无限增长——但那是**同一张画像的 delta**，不是新画像。这是"最多"这个问题的真正边界：**静态快照 12 张，带切片就没有上限，且没有意义。**

### 9.3 12 张清单

| 编号 | 画像 | 回答的决策问题 | 主要来源 | 归属 |
|---|---|---|---|---|
| E1 | 客群可得性 | 我要找的人到场多少 | 观众身份/职级/地域、到场角色构成 | 展商独占 · **匹配核心** |
| E2 | 竞争密度 | 我在这儿能不能被看见 | 展商名录、竞品数、头部占位、展位分区 | 展商独占（读法） |
| E3 | 成本效率 | 一个有效线索多少钱 | 展位价带、附加费、CPL、往届线索量 | 展商独占（口径） |
| E4 | 展位可得性 | 现在还能不能拿到位置 | 余量、售罄速度、早鸟窗口、报名截止 | 展商独占 |
| E5 | 交付可行性 | 我能不能顺利搭起来 | 层高承重、货运通道、指定搭建、进场窗口 | 展商独占 |
| E6 | 历史兑现 | 上届我赚回来了吗 | 该展商上届线索/成交/花费 | 展商独占 · **私有** |
| B1 | 供给覆盖 | 有没有我要的货 | 目标品类展商数、头部品牌、新品首发 | 采购商独占（读法）· **匹配核心** |
| B2 | 供给质量 | 来的靠不靠谱 | 复展率、展商资质、往届口碑 | 共享（采购商主导） |
| B3 | 效率成本 | 值不值得跑一趟 | 差旅、天数、展馆面积→步行成本 | 采购商独占（口径） |
| B4 | 干扰度 | 多少时间是白花的 | 同行/服务商/终端/学生占比、推销密度 | 采购商独占 |
| B5 | 行程节奏 | 去了怎么走 | 同期活动排期、展馆分区、开放日、对接会 | 采购商独占 |
| B6 | 时效窗口 | 现在动不动 | 预登记截止、举办月份、撞期、热度曲线 | 共享 |

### 9.4 为什么不该超过 12

三条硬约束，只有第一条是工程的，后两条是统计和认知的：

1. **字段重叠率超过 70% 后，拆分只增加维护成本。** E2 和 B1 读的是同一份展商名录——展商看"竞品密度"，采购商看"可选项数"。分成两张是对的（决策问题不同），再往下分就是抄字段了。
2. **样本量会被稀释。** 参考表 120 条标注只够拟合 5 个权重。画像拆到 96 张，每张平均 1 条标注，权重全部不可估。这是统计约束，不是工程约束。
3. **用户一屏只能处理 3~5 个判断维度。** 12 张画像不等于给用户看 12 张——每次只呈现 3 张，按其角色 + 当前决策阶段选。

### 9.5 唯一值得增加的维度：同一画像的双向解读

不是加画像，是加**视角切换**。这是整个系统性价比最高的设计：

| 同一份字段 | 展商读作 | 采购商读作 |
|---|---|---|
| 到场者结构 | **客户密度**：我要找的人占几成 | **干扰度**：同行/服务商/推销占几成 |
| 品类集中度 | **同质化风险**：我能否被看见 | **一站式效率**：一次能见多少供应商 |
| 展商名录头部占比 | **门槛**：我够不够格 | **可信度**：头部都来了，说明不是野展 |
| 复展率 | **在位者满意度**：说明还有坑位 | **稳定性**：明年还能来 |

字段抄一份，结论反着出。这让一个展会能同时对两类用户给出可用答案，而不用把数据存两遍。

### 9.6 落地

**12 张画像 ≠ 12 张表。** 它们引用同一批 41 个字段，落到 6 张表即可（见第 8 节）。画像层是**查询 / 视图**，不是存储单元——这一点搞反了，数据库会被拆成十几个只有 3 个字段的表。

## 10. 展商侧 E1–E6 的实现

### 10.1 先否掉一件事：E1–E6 不是"6 个权重"

"每一项都有各自的权重"这个直觉，隐含了一个错误前提：六个画像可以用加权和合成一个总分。**加权平均的数学性质是"一项极差可以被其他项抵掉"，而展商决策里最不能接受的恰恰就是这个**——消防不过、没位置、到场的人全不对口，任何一条都不该被"价格便宜"抵掉。

六项其实分三种角色，聚合方式完全不同：

| 角色 | 画像 | 聚合方式 | 为什么 |
|---|---|---|---|
| **门限** | E4 展位可得性（**仅"来不及"这一种情形**）、E5 交付可行性 | 布尔判断，不满足即停 | 约束不可补偿 |
| **提示** | E4 的其余部分（紧迫度六档） | 不入判定链，只影响行动时机 | 证据不足以下否决 |
| **计算** | E1 客群可得性、E2 竞争密度、E3 成本效率 | 乘性，不求加权和 | "到场人数"和"可见度"是相乘关系，不是相加 |
| **校准** | E6 历史兑现 | 回写系数，不进当日决策 | 它的作用是修正前三项的假设，不是给本次打分 |

**v1 的实际判定顺序（字典序，非加权）：**

```
1. E5 硬约束不满足            → 停 / 输出额外成本
2. E4 窄门限（≤3 天或已结束）  → 停
3. E1 观众/展商比 < 8         → 大幅降级（实测触发 0 次，待重标定）
4. E2 折扣 k（有名录才算）     → 乘到 E1
5. E3 N* 对比                 → 用户侧最终确认
```

用字典序而不是权重，是因为加权和会把"消防不过"和"价格便宜"放同一个天平上；
前者是约束、后者是偏好。v1 只有 80 个样本、0 条标注，标定不出任何有意义的系数。

**结果：进计算的只有 3 个乘性因子，2 个门限，1 个校准回路。需要标定的参数从 24 个降到 3 个（见 10.4）。**

### 10.2 E1 客群可得性

**输出：目标角色到场人数区间 `[P10, P50, P90]`，不是点值。** 三个估计量相乘（总人数 × 占比 × 折扣），误差会复合，给点值就是假精确。

```
目标角色人数 = 专业观众数 × 角色命中率 × 职级折扣
角色命中率 ∈ [0.05, 0.45]   按品类匹配度分三档
职级折扣 = 决策层 + 0.3×建议层 + 0.1×执行层
```

**v1 唯一能算的硬指标是"观众/展商比"**：

```
观众展商比 = 专业观众数 ÷ 展商数
≥25 客源相对充裕 ｜ 10~25 正常 ｜ <8 摊薄严重
```

这是公开数据就能拿到、且最能反映"每个展位能分到多少人"的指标。10 万观众 / 3000 展商 = 33；2 万观众 / 2500 展商 = 8，后者再对口也不值得去。

> **实测（批次 2，25 个可算比值的展）**：比值全部落在 15.4 ~ 1280 之间，**没有一个是 <8 的，甚至没有一个是 <10 的**。
> 也就是说，这个门限在真实数据上触发 0 次，跟 E4 的截止日门限是同一个命运。
> 两个原因叠加：① 观众数和展商数都是宣传口径，主办方都有动力把分子写大；
> ② 口径混用（人次 vs 人数）本身带来 1.8~2.5 倍偏差，比 8~10 这一档的宽度还大。
> **结论：E1 现在卡在"只有 25/94 能算"，不是卡在阈值；阈值应改成按品类分位，而不是固定 8 倍。**
> 详见 `docs/批次2-规模与属性抽取.md` §4.2。

- **降级**（拿不到观众构成时）：用「品类匹配度 + 观众/展商比 + 城市能级」三档定区间，`confidence=低`
- **失效条件**：观众数含直播观看或公众开放日；分母用了"人次"而非"专业观众数"

### 10.3 E2 竞争密度

**输出：可见度折扣系数 `k ∈ [0.4, 1.0]`，乘到 E1 上。**

```
k = 1 / (1 + max(0, 同品类同价位竞品数 - 3) × 0.12) × 头部占位惩罚 × 新展商激励
头部占位惩罚：Top5 全在 ×0.7 ｜ 来了 2~4 家 ×0.85 ｜ ≤1 家 ×1.0
新展商激励：新展商占比 >40% ×1.05
```

**"减 3"是关键设计**：前 3 家同品类竞品是正常的，它说明这是个有效市场；第 4 家开始才是真分流。直接按竞品数倒数算，会把所有成熟展会都判死。

- **降级**（拿不到价位带）：只按品类算，`k` 上限压到 0.85
- **失效条件**：展馆分区未知时 `k` 系统性高估——主通道位和角落位差 3~5 倍，而名录里看不到位置

### 10.4 E3 成本效率

**输出：所需线索数 `N*`（用户侧算）+ 可达线索数（平台侧估），不给 CPL 绝对值。**

```
N* = (展位费 + 搭建 + 差旅 + 人力) ÷ (客单价 × 成交率)
可达线索 = 目标角色人数 × 接触率 × 留资率      接触率×留资率 ≈ 1.5%~4%（假设值）
判断：可达线索下界 ≥ N* → 可去
```

**这个设计的核心是"把不可知的量挪到用户侧"。** `N*` 只用用户自己的数据（客单价、成交率、成本），平台一条都不需要知道；平台只负责估"这个展能给你多少条线索"。于是冷启动不需要任何历史成交数据——这是整个展商侧能在 v1 跑通的唯一原因。

- **降级**（用户不填客单价）：退回定性提示"每线索成本需低于 客单价×成交率"
- **注意**：`1.5%~4%` 必须显式标注为假设，且随 E6 回写修正

### 10.5 E4 展位可得性

> **v2 修订（2026-11-03，据批次 1 实测）**：E4 原设计的两个因子都拿不到数据——
> 报名截止日 **0/80**、售罄/余量 **0/80**（需批次 3 名录）。只剩「距开展天数」可用
> （35/80）。按此在全量数据上跑一遍，**门限触发次数 = 0**。
> 因此 E4 从「门限」降级为「窄门限 + 紧迫度提示」。完整证据与取舍见
> `docs/批次1b-往期兜底与E4重标定.md`。

**输出：六档紧迫度（只提示）+ 一个极窄的门限（只否决"来不及"）。**

```
门限（唯一可否决）：本届已结束，或距开展 ≤ 3 天
紧迫度：>180 充裕 ｜ 90~180 正常 ｜ 45~90 偏紧 ｜ 15~45 紧 ｜ 4~14 很紧 ｜ 0~3 基本不可能
待批次 3 补：余量率 = (展位总数 − 已报名展商数) ÷ 展位总数   ← 有了它 E4 才能恢复门限
```

- **为什么门限必须窄**：假否决的代价不可逆（用户永久失去一个机会），漏判可以恢复。
  在 44% 覆盖、零售罄证据的情况下，任何宽门限都会大面积误杀。
- **档位命名**：不用 `closed` 描述"距开展 5 天"。那只是"没好位置"，不是"关门了"，
  两者对用户的行为指引完全不同。
- **失效条件**：总余量充足但热门分区售罄，即"有位但没好位"——这需要分区数据，`B` 级

### 10.6 E5 交付可行性

**输出：核查清单 + 三态结论（通过 / 需额外成本 X / 不可行），不打分。**

八条布尔项：层高≥特装高度、承重≥设备重量、货运通道≥车辆宽、进场时间窗≥搭建工时、是否强制指定搭建商、电力容量、消防（明火/材料等级）、吊点。

**这一项最不该有权重**：它是约束不是偏好。一旦加权，就会出现"其他项都不错所以消防不过也能去"这种荒谬结论。任一不满足 → 直接输出额外成本或不可行。

### 10.7 E6 历史兑现

**输出：偏差系数 + 一句话复盘。不进当日决策，只回写。**

```
偏差 = 实际有效线索 ÷ E3 预估线索
连续两届偏差 <0.5 → 该展 E1 系数下调一档
```

**它是全系统唯一的闭环入口。** v1 表可以先空着（冷启动必然没有），但 `exhibition_outcome` 的结构必须留，否则权重永远只能靠经验值。

### 10.8 全系统只有 3 个可调参数

| 参数 | 取值 | 怎么定 |
|---|---|---|
| 角色命中率三档值 | 0.05 / 0.2 / 0.45 | 3~5 个真参过展的人给区间 |
| 接触率 × 留资率 | 1.5%~4% | 同上，或等第一届自采数据 |
| E2 分流斜率 | 0.12 | 同上 |

**对比：若按"6 项各有权重、每项内部再加权"做，需要标定 20+ 个参数。** 参考表 120 条标注只够拟合 5 个权重——放大到 24 个权重需要数千条标注，而这个项目一届只产几百条。这不是工程选择，是统计约束。

### 10.9 v1 实现顺序（按"不依赖任何人配合"排序）

| 序 | 画像 | 为什么排这个位置 |
|---|---|---|
| 1 | E1 的观众/展商比 | 纯公开数据，当天可算，不依赖任何录入 |
| 2 | E4 的紧迫度提示 | 纯时间函数，零数据依赖；**注意不是"截止日倒计时"，截止日实测 0% 覆盖** |
| 3 | E3 的 N* 计算器 | 只需用户填 4 个数（成本/客单价/成交率） |
| 4 | E2 的竞品数 | 依赖品类标签树，是 P0 前置 |
| 5 | E5 的固定核查清单 | 无数据也能上，先让用户自己勾 |
| 6 | E6 留表不填 | 冷启动必然为空，只建结构 |

**v1 实际只剩 E1 + E5 真正参与判断。** E2 要等名录、E3 要等用户输入、
E4 降为提示、E6 空表——这个结论不好看，但比假装六项都在跑要安全。

## 11. 待确认
