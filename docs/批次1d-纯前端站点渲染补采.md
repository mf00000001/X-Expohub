## 1. 先诊断，再动手

上浏览器是最贵的解法（装环境、单站 3~30 秒、要处理反爬）。所以先跑 `probe_spa.py`
判断每个站属于哪一类，不同类的解法完全不同：

| 类型 | 数量 | 判断依据 | 解法 |
|---|---|---|---|
| `ssr_embedded` | 2 | HTML 里有 `__NUXT_DATA__` 且 >2000 字 | 解 JSON 即可，不用浏览器 |
| `api_hint` | 0 | JS 里能看出 API 基址 | 直接打接口 |
| `shell_only` | 17 | 只有 `<div id="app">` + 一堆 JS | 只能渲染 |

诊断结果值得记一笔：**没有一个是 `api_hint`**。国内展会站的 SPA 基本是"整页 SSR + 前端接管"，
不是前后端分离的数据接口模式，所以"找接口比渲染便宜"这条经验在这里不成立。

`cbd-fair` 和 `waic` 虽然是 `ssr_embedded`，但它们用的是 Nuxt 3 的 devalue 序列化格式
（一个扁平数组，靠下标互相引用），自己解要写一套 revive 逻辑。**渲染反而更快更稳**，
所以最终 19 个站全部走渲染，没有为这 2 个站单独写解析器。

## 3. 三个必须处理的坑

### 3.1 导航中断 ≠ 抓取失败

第一轮 16 个站有 7 个报：

```
Page.goto: Navigation to "https://www.ciftis.org/" is interrupted by another navigation
```

原因是首页会立刻 JS 跳转到 `/zh/` 或 `/home`，Playwright 认为第一次导航被打断而抛异常。
**但页面其实已经正常加载了。** 当成失败处理，会把能采的站误判成采不到。

处理：吞掉这个特定错误，等 1.2 秒让二次跳转落定，然后照常取文本。7 个站全部转为成功。

### 3.2 一个 page 会污染后面所有站

第一轮用同一个 `page` 对象循环 16 个站。一旦某个站的导航被中断，那个 page 的状态就脏了，
**后面所有站都跟着报 `interrupted`**——而它们本身完全没问题。

这是最容易误判的一种情况：看到连续 7 个站失败，第一反应是"这些站都反爬"，
实际上只是第一个站把 page 弄脏了。改成每站 `ctx.new_page()` 后立即全部通过。

### 3.3 渲染不是单调变好的

`auto-shanghai` 静态页正文 1143 字，渲染后只剩 **143 字**——反爬拦截或地区跳转把内容换掉了。

如果无条件"有渲染结果就用渲染结果"，会把本来够用的数据换成空壳。
所以 `body_path()` 改成**比大小**：渲染版更大才用渲染版。

实际结果：19 个站里 16 个用了渲染版，3 个回退到静态版。

## 4. 子页抓取：收益很低

首页常是门户（新闻轮播 + 导航），展期在"关于/参展"页。所以加了 `--subpages`：
渲染完首页后，按链接文字挑 1~2 个同域子页再渲染。

实测在 4 个最弱的站上试，**只有 1 个（智慧城市 `scie`）抓到了子页**。
其余 3 个的导航是 hover 展开的二级菜单，`querySelectorAll('a')` 取不到，
要模拟鼠标悬停才能拿到链接。

**结论：这个功能的投入产出比不划算**，默认值保留 2 但不要指望它。
真要补，代价更大的是"模拟交互"，不是"多渲染几个页面"。

## 5. 一个模型表达不了的事实：广交会是三期

广交会官网如实写着：

```
第140届广交会
第一期 先进制造   2026年10月15日-19日
第二期 品质家居   2026年10月23日-27日
第三期 美好生活   2026年10月31日-11月4日
```

我们的 `start_date` / `end_date` 只有一对字段，只能装下第一期，于是这条记录被判成
`dates_status = past`（10 月 15 日已过）。**而实际上今天（11 月 3 日）第三期正在办。**

这不是抽取错误，是**数据模型不足**。广交会、华交会这类分三期办的展会，
以及"主展 + 同期子展"结构，都需要 `expo_phase` 子表：

```
expo_id | phase_no | phase_name | start_date | end_date
```

短期处理：在 `notes` 里保留"该展分 N 期"的提示，并把这个展会的人工确认项标出来。
中期：批次 2 的时候加子表——反正采购商判断"哪天去"本来就需要分期信息（B5 行程节奏）。

## 7. 剩下的 18 个「无日期」

渲染 + LLM 之后仍有 18 个站完全没有日期。分两类：

| 类型 | 例子 | 真实原因 |
|---|---|---|
| 门户站，展期在二级页 | `snec`、`scie`、`ciftis` | 首页全是新闻，展期在"展会介绍"里，且导航要 hover 才能展开 |
| 官网确实没写 | 少数垂类展 | 只在公众号发布，官网是空壳 |

**这 18 个不应再靠技术手段硬啃。** 两条更便宜的路：
1. 每站花 2 分钟人工确认展期（18 × 2 = 36 分钟一次性投入，且展期一年只变一两次）
2. 走 `import_csv.py` 人工录入通道，顺带把 venue / organizer 一起补

批次 3 名录抓取时如果发现这些站有独立的"展商名录"页，可以顺路拿到届次信息。
