# 智能匹配工作流（Match Workflow）

> 把「智能推荐」从散落的规则函数 + 单点云端大模型调用，重构为一条**显式、可观测、
> 可降级的多阶段匹配工作流**。全链路本地运行（毫秒级、零云依赖、零超时）；
> 云端 LLM 仅作为可选的「AI 解读」增强，失败/超时自动降级为本地解释。

最后更新：2026-09-16 ｜ 相关代码：`expohub-backend/app/modules/matching/{textkit,workflow,recommendations}.py`

---

## 1. 为什么要重构

原「智能匹配」的四个精度硬伤（实测定位）：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 关键词评分 = **字符集合交叠**（"采购一台车床"与"电视机"都能蹭分） | 无分词/无权重/无同义词，精度极低 |
| 2 | 补录需求用了**非标品类**（家用电器/新能源/医疗器械…），与 18 个标准展区品类对不上 | 这些需求品类匹配直接断链 |
| 3 | 召回**截断到最近 500/2000 条**展品（全库 10027 条） | 大量展品永不出现 |
| 4 | 「推荐说明」按钮依赖**云端大模型**（实测单次 22s+，曾 15s 超时必挂） | 慢、要钱、要网、演示易翻车 |

## 2. 工作流拓扑（S0 → S5）

```
S0 画像装配    展商画像：行业领域 + 展品品类 + 关键词(带权重) + 价格带 + 展位热度
    │          需求画像：标题核心词(末词加权) + 描述细节词 + 品类(归一化) + 预算
S1 多路召回    品类通道（归一化后精确/同父组） + 关键词倒排通道（IDF 加权）
    │          —— 同义词/上位词/复合词拆分同步展开，保证与打分层一致
S2 候选过滤    状态过滤（pending）/ 剔除自家发布 / 剔除已应标
S3 多信号打分  category 品类相似度 · keyword 关键词覆盖(两层) · portfolio 展品池命中
    │          · budget 预算吻合 · freshness 新鲜度(半月衰减) · quality 热度
S4 排序截断    加权总分降序（按可用信号归一化） + 阈值门控 + Top-K
S5 解释生成    逐信号本地模板理由（"品类精确匹配：机械 / 关键词命中：加工中心、数控…"）
```

**可选增强（S6）**：`✨ AI 生成推荐说明` 仍走 `/api/ai/generate`（云端、按钮触发），
但**失败/超时自动降级**为 S5 本地解读 —— 主链路永不依赖云端。

### 打分权重（唯一调参入口，`workflow.py` 头部常量）

| 方向 | category | keyword | portfolio | budget | freshness | quality |
|---|---|---|---|---|---|---|
| 展商 ← 采购需求 | 0.32 | 0.38 | 0.10 | 0.10 | 0.10 | — |
| 采购需求 ← 展品 | 0.32 | 0.40 | — | 0.10 | 0.08 | 0.10 |

信号缺失（如预算未填）时按**可用权重重新归一化**，不会拉低分数。

## 3. 文本层关键设计（textkit.py）

- **分词**：jieba 优先（领域词表 add_word），缺库自动降级为二元组——功能不缺失；
  保持原序输出（用于"末词=中心语"加权的标题查询）。
- **品类归一化**：40+ 别名映射（家用电器→电子及家电、工业自动化→机械、新能源→能源…）+
  后缀剥离（"机械类"→"机械"），修复跨体系品类断链。
- **同义词三层**：
  - 真同义词族（双向 0.4）：数控↔CNC、光伏↔太阳能、数据线↔Type-C…
  - 上位词→下位词（单向 0.5）：查询"家电"命中"空调"，反之不成立（防并列词互蹭）
  - 复合词拆分（0.7）："汽车轮胎"⊃"轮胎"、"智慧路灯"⊃"路灯"
- **IDF 与匹配同空间**：中文词按**原文子串命中**统计 df（避免分词差异让"新能源车"
  这类词权重虚高 —— 它在"新能源车衣"里被切碎）；拉丁词按 token 精确匹配（防 `ce`⊂`oceanstor`）。
- **覆盖两层**：标题核心词 70% + 全量（含描述）30% —— 描述里的认证/电压/数量词不再稀释核心匹配。
- **规格词过滤**：200MW、550W、IP65 等含数字词不参与打分（保留 5G/4K 等业务词）。

## 4. 性能与缓存

| 项 | 值 |
|---|---|
| 语料构建（10k 展品分词+IDF+倒排） | ~1.5s，**启动后台线程预热**（测试环境跳过） |
| 数据变更失效 | 指纹 = (已发布数, max(id), max(updated_at))，变更自动重建；兜底 TTL 10 分钟 |
| 推荐调用（热态） | 展商侧 40–100ms；展品侧 30–90ms（含 595 召回 + 全量打分） |
| 云端依赖 | **零**（LLM 仅可选增强） |

## 5. 评测（scripts/match_eval.py，金标=需求核心词⊂产品名）

在 `expohub.db` 临时副本上对比新旧算法（32 条需求中 24 条有对应展品）：

| 指标 | 老算法 | 新工作流 |
|---|---|---|
| 方向一 P@5（需求→展品） | 0.00 | **0.86** |
| 方向一 P@10 | 0.00 | **0.85** |
| 方向二 P@10（展商→需求） | 0.84 | **1.00** |
| 引擎 | 字符交叠+截断 | 本地工作流（可解释） |

> 老算法 P=0 的原因：它只扫"最近 500 条"展品，而演示库把大部分品类排在窗口之外。
> 8 条需求因演示库无对应展品（咖啡机/卫浴/球泡灯等）被评测透明跳过。

## 6. API 响应约定

三个端点返回结构兼容旧契约，并新增：

```jsonc
{
  "data": [ { "match_score": 79, "match_level": "high", "reasons": ["品类精确匹配：…"], ... } ],
  "pipeline": {                    // 工作流运行摘要（前端展示「⚡ 本地匹配工作流」）
    "engine": "match-workflow-local", "recalled": 4, "scored": 3, "returned": 3,
    "total_ms": 106.0,
    "stages": [ {"name": "S0 画像装配", "ms": 62.3, "in": 0, "out": 18, "note": "…"} ]
  }
}
```

- `GET /api/recommendations/for-exhibitor` — 展商推荐采购需求
- `GET /api/recommendations/for-buyer` — 买家推荐展品（最新 pending 需求驱动）
- `GET /api/recommendations/score-procurements?ids=1,2,3` — 列表页实时匹配度打分
- `GET /api/procurements/{id}/recommendations` — 采购详情推荐展品（含 AI 降级）
- 发布采购时：工作流逐展商打分，达到阈值（55）的 Top5 收到带匹配度通知
