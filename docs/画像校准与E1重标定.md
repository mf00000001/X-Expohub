# 画像校准与 E1 重标定

> 日期：2026-11-03 ｜ 参数版本：`v2-2026-11-03` ｜ 库：`expohub-backend/persona.db`
> 对应代码：`app/modules/persona/bands.py`、`scripts/persona/compute_persona.py`
> 上游文档：`docs/展会画像-维度清单.md`（10.1 / 10.2 / 10.5）、`docs/批次2-规模与属性抽取.md`

这份文档记录一件事：**画像层第一次拿真实数据算完之后，哪些参数被推翻了、改成了什么、依据是什么。**

在这之前，E1 到 E6 的档位全是拍的。拍的参数有个隐蔽的坏处——它不会报错，只会安静地永远不触发。
本文的核心结论就是：v1 的 E1 门限在 27 个真实样本上**一次都没触发**，等于没写
（后来补采把样本扩到 35 个，结论不变，最低仍是 13.3）。

---

## 1. E1 重标定：为什么 8 倍门限是假的

### 1.1 v1 的设定

`docs/展会画像-维度清单.md` 10.2 最初给的档位是按"常识感"定的：

| 档位 | v1 门限 | 直觉含义 |
|---|---|---|
| 充裕 | ≥25 | 每个展位背后有 25 个以上专业观众 |
| 正常 | 10~25 | — |
| 偏薄 | 8~10 | — |
| 摊薄严重 | < 8 | 参展商抢不到人 |

这条逻辑链本身没错：观众/展商比低 = 分母是一堆竞品在抢同一批客。但 8 这个数没人验过。

### 1.2 真实数据打脸

批次 2 抽出 81 个有正文的站，其中**观众数与展商数同时有值的 27 个**才能算比值。
第一版把它们排序，得到 v2 的分位；补采把样本补到 35 个之后重算，得到 v3：

```
v2（n=27）人次÷2 归一后：P25 = 24.5   P50 = 60.0   P75 = 75.0
v3（n=35）人次÷2 归一后：P25 = 25.4   P50 = 40.0   P75 = 73.3
v3 未归一（原始口径）：  P25 = 33.7   P50 = 62.5   P75 = 75.0
最低的一个：             sh-gift  40000人次 / 1500 展商 = 26.7（归一后 13.3）
```

**P50 从 60 掉到 40**，是补采捞回来的 8 个展大多落在 30~70 之间（cmef 40、
automechanika 34、yongkang 44、b-muying 39）——原来那 27 个样本偏"头部大展"，
中位数被顶高了。这正是"相对档位"该有的反应：样本变了，尺度就得跟着变。

**35 个展里，最低的仍然是 13.3。** 那条 `< 8 判摊薄` 的硬门限，在真实数据上触发次数为 0。

触发 0 次的规则不是"严格"，是"不存在"。它给下游一个虚假的安全感：以为系统在筛，
其实每一项都过了。这比没有这一项更危险——因为"通过了检查"会被当成"数据支持"。

### 1.3 v4：按样本四分位切

```
ample   ≥ 76.4   （样本前 25%）
normal  ≥ 60.0   （P50 ~ P75）
thin    ≥ 27.4   （P25 ~ P50）
severe  < 27.4   （样本后 25%）
```

**为什么敢用分位而不是绝对阈值：** 这几个数全是主办方的宣传口径，绝对值天生不可比
（谁都想把分子写大、把"人次"写成"人数"）。但"在同期样本里排第几"是可比的。
分位把这个不可比的量变成了可比的序。

**代价必须写清楚：** 这是**相对档位**，换样本就得重算。所以
- 版本号写进常量名（`RATIO_CALIBRATION["version"]`），落进 `persona_param`；
- 提供 `--calibrate` 模式随时打印"当前样本分位 vs 常量"，偏差 >10 就提示该重标了。
- **这一条已经真实发生过两次**：
  - 样本 27→35（官网补采），偏差 20.0，v2 → v3（24.5/60.0/75.0 → 25.4/40.0/73.3）
  - 样本 35→43（接入去展网第三方源），偏差 20.0，v3 → v4（40.0 → 60.0）
  - 各版都留在 `RATIO_CALIBRATION["superseded"]` 里可查。

#### v4 这次漂移暴露了一个结构性偏差

P50 从 40.0 跳到 60.0，涨了 50%。不是抖动，是样本结构变了——新补的 8 个
（进博会、服贸会、高交会、SIAL、HOTELEX、面辅料展、门窗幕墙、义乌小商品）
全是**能查到第三方数据的知名大展**，观众基数天然大、比值天然高。

> **"能拿到数据的展" ≠ "随机抽样的展"。**

这个偏差是方向性的、会重复的：每补一批数据，补进来的多半还是大展，分位还会往上走。
它不影响"相对排序"这个用途（大展本来就该排在前面），但会让绝对档位线随时间单调上移。
如果将来要拿档位做跨年比较，必须换成固定档位或另找锚定样本。

#### 另外，这 8 个的比值是下限估计

去展网观众数实测**系统性偏低 20~25%**（CMEF 15 万 vs 官网 20 万+、CHINAPLAS 25 万 vs 31 万+），
展商数则较准。成对同源取数保证了不混源、比值不失真，但比值本身偏保守。
详见 `docs/第三方数据源接入.md`。

### 1.4 `severe` 的正确读法

这是最容易被误读的一处，必须在产品文案上卡死：

> **`severe` ≠ "这个展不能去"，`severe` = "在本样本 43 个可比值里排后 25%"**

它是个**横向比较位**，不是纵向绝对判断。sh-gift 的 13.3 仍然意味着"每个展位对着 13 个
专业观众"，现实里这不是灾难，只是相对最薄。把它渲染成红牌会误导用户。

### 1.5 绝对下限单独保留

```python
RATIO_ABS_FLOOR = 5.0   # 低于 5 无条件 severe，不管分位怎么切
```

理由：分位切法有个漏洞——如果未来样本整体变差（比如混进一批小展），
P25 会跟着往下掉，`severe` 就永远只在最低那 25% 上，绝对水平再烂也不报警。
"每个展位分不到 5 个观众"是口径无关的常识判断，得有一条不随样本漂移的底线。
当前 43 个样本不触发，它是给未来脏数据准备的。

### 1.6 一个必须落进参数表的旋钮：`VISIT_TO_PERSON = 2.0`

维度清单给的范围是 1.8~2.5，取中点 2.0。43 个可比值的展里有 **11 个报的是人次**，
折算后其中 **7 个直接跨档**：

| 展 | 原始比值 | 归一后 | 档位变化（v4） |
|---|---|---|---|
| sh-gift | 26.7 | 13.3 | thin → **severe** |
| ningbo-lighting | 30.0 | 15.0 | thin → **severe** |
| icif | 33.3 | 16.7 | thin → **severe** |
| yongkang-hardware | 43.9 | 21.9 | thin → **severe** |
| ec-expo-yiwu | 57.7 | 28.9 | thin（27.4 线上方一点） |
| ciif | 69.6 | 34.8 | normal → **thin** |
| ceramics-china | 94.3 | 47.2 | normal → thin |

（`cwp` 120→60 正好压在 P50 上，折算前是 normal、折算后还是 normal，但位置从"刚过线"变成"正好卡线"。）

系数从 2.0 调到 1.8，sh-gift 就是 14.8，调 2.5 就是 10.7——**跨档**。
所以它不能散落在代码里，必须进 `persona_param`（键 `visit_to_person`），改它有据可查。

同时 `compute_all()` 增加 `ratio_basis` 字段区分三种来源：

- `person` —— 页面直接报人数，比值可信（当前 30 个）
- `converted_from_visit` —— 页面报人次，比值 = 原始数 ÷ 2，**这个 2 是假设不是实测**（当前 11 个）
- `unknown` —— 没有比值（当前 51 个）

另有一个 `ratio_source` 字段区分一手/二手（`official` / `thirdparty`），
它不参与计算，只用于审计——见 `docs/第三方数据源接入.md`。

同样的 15.0，`person` 来的和 `converted_from_visit` 来的，可信度不一样。下游要能看见这个差别。

## 2. E2 竞争密度：暂停，而不是调参

原公式 `1 / (1 + max(0, 竞品数 - 3) × 0.12)` 的前提是"竞品数在个位数到几十"。
批次 3 实测把这个前提打穿了：

| 展 | 名录条数 | 同品类竞品 | 算出因子 |
|---|---|---|---|
| CMEF | 13,306 | 10,449 | **0.0008** |
| 高交会 | 929 | — | 0.0089 |

竞品数一过 11，因子就跌破 0.51；到 10,449 时基本等于 0。
**把它乘到 E1 上，等于把这两个展的客群估计直接归零——比不乘更糟。**

更根本的问题是数据不够：94 个展里
- 能拿到可计条数名录的：**3 个**（3.2%）
- 有品类标注能算"同品类"的：**2 个**

在一个 n=2 的样本上标定参数，标出来的只是自己的假设，套了个公式的壳。

**处理方式：** 不是"调小系数"，而是**关掉**。`E2_STATUS["enabled"] = False`，
`e2_discount()` 恒返回 `(None, 原因)`。保留函数签名是给下游一个稳定接口——
调用方拿到 `None` 就知道"这一项现在是关的"，而不是拿到 0.0008 然后默默把 E1 乘没。

重标定的前置条件（没满足之前不要重开）：
1. 名录可得率上到 30% 以上；
2. 品类标注上到 30% 以上；
3. 公式改成按**竞品占比**（同品类条数 / 总条数）而非绝对数——占比不会随名录规模饱和。

## 3. E4 展位可得性：换锚点 + 降级为提示

### 3.1 原来的主因子不存在

批次 1 实测 80 个可用站，**报名截止日填充率 0%**（63 个页面一个字都没写，
剩下的写"额满即止"）。E4 原设计挂在"截止日倒计时"上，这个锚点在真实数据里没落地过。

能用的只剩开展日：填充率 52.5%（94 个展里 44 个有本届日期）。

### 3.2 换成两组档位，且只有一个是门限

**A 组（有截止日，原设计，最准）** — `DEADLINE_BANDS`
```
>120 天 ample ｜ 60~120 normal ｜ 0~60 urgent ｜ 已过 closed
```

**B 组（无截止日，退回开展日）** — `START_WINDOW_BANDS`
```
>180 ample ｜ 90~180 normal ｜ 45~90 tight ｜ 15~45 urgent ｜ 4~14 critical ｜ 0~3 impossible
```

B 组的档位名刻意不用 `closed` / `soldout` 这类**容易被读成"去不了"**的词。
距开展 5 天不等于关门，只等于"好位置大概率没了"。前者是门限，后者是提示。

### 3.3 `role` 字段是这次改动的核心

```python
HARD_STOP_DAYS = 3
role = "gate" if days_left <= 3 else "advisory"
```

**唯一的门限是"来不及"**：本届已结束，或距开展 ≤3 天。其余全部 `advisory`，不得否决。

为什么把 44% 覆盖的粗粒度信号从门限降成提示：假否决的代价是**用户永久失去一个机会**，
比漏判更不可逆。而售罄/余量数据覆盖率是 0——E4 没有任何证据说"已经没位了"，
它只有资格说"来不及了"。

### 3.4 往届日期绝不能算出 `closed`

这是最坏的一类假否决的实现路径：往届日期算出的 `days_left` 是负数，直接进档位就得到 `closed`，
等于用"去年已经办完了"去否决"今年还去不去"。

两道防线：
- `days_left < -90` → 当成往届，`band=unknown`、`role=advisory`、不返回 `days_left`；
- `compute_all()` 里 `dates_status == "past"` 时根本不走 B 组，只出季节先验。

### 3.5 往届日期的正确用法：季节先验

`season_prior()` 只导出一件事——这个展通常几月办。年份推不出来（年展 / 双年展 / 停办一轮长得一样），
所以只给月份并标 `estimated=True`；距今 >24 个月标 `stale=True`。
用途是行程节奏、撞期判断、详情页那句"该展通常在 11 月举办"，**不进 E4 计算**。

## 4. 参数表（已落 `persona_param`，version=4，值取 v4）

| key | 值 | 说明 |
|---|---|---|
| `ratio_bands` | 76.4/60.0/27.4/0 → ample/normal/thin/severe | E1 分档主表（v4） |
| `ratio_calibration` | `{version: v4, n=43, p25, p50, p75, raw_p25…, superseded, caveat}` | 标定样本与版本，换样本对账用 |
| `visit_to_person` | `2.0` | 人次→人数折算（跨档敏感，见 1.6） |

分母（展商 750）较准，分子（观众 11 万）比官网口径低约 20%，真实值应在 180 左右。

## 6. 已知缺口（按影响排序）

### 6.1 E1 覆盖率 46%（43/94）——仍是最大的洞，但两条路都走到头了

51 个 `unknown` 的构成：

| 情况 | 个数 | 能不能补 |
|---|---|---|
| 两个数都缺 | **41** | 只能靠第三方源，且必须成对 |
| 只缺展商数 | 6 | 按"不混源"原则**不补**（补了就成半真半假） |
| 只缺观众数 | 4 | 同上 |

**41 个双缺的展，去展网这条第三方路已经走到尽头。** 2670 个详情页全量跑完，
没有一个能以 ≥0.80 分唯一命中：40 个是"无匹配或分数不够"，1 个是命中两条同名（`ccbef`）。
也就是说再扩抓取量不会有结果——瓶颈不在抓取广度，在这批展本身没有可对齐的第二来源。

那 10 个"只缺一个"的是这条原则的活证据：**有数据可选，但选了就是混源。**
观众数来自 A 源、展商数来自 B 源，比值会凭空偏 20~25%，比 `unknown` 更糟——
unknown 是诚实的，假数是误导。

两轮补采的成绩对比：

| 轮次 | 手段 | 可算比值 | unknown |
|---|---|---|---|
| 批次 2 | 官网首页结构化字段 | 27 | 67 |
| 补采 | 换目标页（历届回顾/展后报告/新闻稿） | 35 | 59 |
| 去展网 | 第三方结构化详情页（成对、不混源） | **43** | **51** |

第一轮靠"换页面找同一份数据"，第二轮靠"换来源找同一组数据"。
两者都遵循同一条：**只接受同源成对，不接受拼凑**。
详见 `docs/E1缺口补采与闸门修复.md` 与 `docs/第三方数据源接入.md`。

### 6.2 `e1_confidence` 94 个全是 `low`——这是诚实的，不是 bug

`e1_target_range()` 只在 `rank_discount != 1.0` 时给 `mid`。而职级构成（决策层/建议层/执行层占比）
在 94 个站里一个都没有，`rank_discount` 永远是 1.0 → 永远 `low`。

按设计，角色命中率是标定值而非实测值时，置信度最高只能到 `mid`。现在连 `mid` 都拿不到，
说明**E1 的区间目前只是一个量级参考，不能当预测值展示**。要提置信度只有两条路：
补职级构成数据，或等 E6 校准回路跑起来用历史兑现率反推命中率。

### 6.3 `prev_*` 只到 4/4/3 → E6 校准回路没启动

批次 2 里 `prev_visitor/prev_exhibitor/prev_area` 分别只有 1/1/0 条；补采后到 4/4/3。
两届对比**只存在于"历届回顾/上届回顾"页**，首页结构性写不了。
E6 需要 `expo_history` 时间序列，表已建但仍为空。

### 6.4 面积口径全按 gross

39 条面积记录（含 8 条第三方源），没有一个页面标"净面积"。`area_caliber` 全填 gross 是
**默认值不是实测值**，用它算"每平米展商密度"会系统性偏低。在拿到净面积之前，面积不参与任何比值。

### 6.5 `auto-china` 的 640 不是错数，是车展品类特征（见 5.1）

一度怀疑是"累计入场人次含公众日"的口径问题。核对后确认：上海/北京车展观众本来就是
80~100 万量级、展商 1000~2000 家，比值天然在数百。它和 `awe`(208)、`fenestration-china`(147)
一起构成右长尾。

**这条记下来是因为它反过来说明了一件事**：同一套门限不能跨品类用。E1 的分位是从
"综合类展会"样本上切出来的，套到"超大型消费展"上会把它们全部判成 ample——
但反过来，如果样本里混进小众专业展，也会整批滑到 severe。将来做品类内部分位是有必要的。

## 7. 怎么重算

```bash
cd expohub-backend

# 0) E1 缺口补采（找历届回顾/展后报告/新闻稿页；静态不够会开浏览器取链接）
../.venv/Scripts/python.exe scripts/persona/probe_reports.py --no-render
../.venv/Scripts/python.exe scripts/persona/probe_reports.py --only <静态失败的 id>
#    然后对拿到新正文的站重抽（load_body 会自动把 data/batch1/report/ 拼上）
../.venv/Scripts/python.exe scripts/persona/extract_scale.py --force --only ...

# 0b) 第三方源（去展网）：抓索引 → 匹配（先看报告）→ 确认后写库
../.venv/Scripts/python.exe scripts/persona/collect_qufair.py --workers 4   # 全量约 4.5 分钟
../.venv/Scripts/python.exe scripts/persona/match_qufair.py                 # 只出报告
../.venv/Scripts/python.exe scripts/persona/match_qufair.py --apply         # 人工核过再执行

# 1) 看当前样本分位与常量差多少（>10 就该重标定）
../.venv/Scripts/python.exe scripts/persona/compute_persona.py --calibrate

# 2) 落库（清空 expo_persona 重算，参数同版本覆盖）
../.venv/Scripts/python.exe scripts/persona/load_persona.py     # 会重算 data_status
../.venv/Scripts/python.exe scripts/persona/compute_persona.py

# 3) 换一个"今天"重算，检验档位随时间的变化（ciie 会从 gate 变 closed）
../.venv/Scripts/python.exe scripts/persona/compute_persona.py --today 2026-11-10

# 4) 人工补数后重载
../.venv/Scripts/python.exe scripts/persona/import_csv.py --template     # 生成 todo.csv
../.venv/Scripts/python.exe scripts/persona/import_csv.py --load data/manual/todo.csv
../.venv/Scripts/python.exe scripts/persona/load_persona.py             # 重新合并入库
```

**顺序不能反**：`match_qufair.py --apply` 必须跑在 `load_persona.py` **之前**。
反过来会被 `load_persona` 用 `merged.json` 的值覆盖（第三方观测本身有 `source_type='thirdparty'` 保护，
不会被删，但 `expo` 表的列会跟着 JSON 走）。当前实现已经用 `if not cell: continue` 避开了覆盖，
但依赖这个细节是脆的——按顺序跑最稳。

**改档位的正确姿势：** 改 `bands.py` 常量 → 跑 `--calibrate` 看分布 → 改版本号 →
落库。**不要直接 UPDATE 数据库里的 `expo_persona`**，下次重算会被覆盖，而且没人知道那份数是怎么来的。
改完必须跑 `bands.self_check()`（`compute_persona.py` 会自动跑，失败项非空就退出）。

## 8. 这轮得到的方法论

1. **参数不触发 = 参数不存在。** 上线任何门限前，先拿真实样本数一遍触发次数。0 次的规则要删或重标，不能留。
2. **在 n=2 上标定，标的是自己的假设。** E2 的正确处理是关掉并写清重开条件，而不是调一个让它"看起来温和"的系数。
3. **假否决比漏判更贵。** 门限只保留口径无关、证据充分的那一条（≤3 天来不及），其余降为提示。用户被误拦一次就再也不来了；被提示错一次还能自己判断。
4. **成对使用、绝不混源。** 观众数来自 A 源、展商数来自 B 源，算出来的比值会凭空偏 20~25%，
   而比值正是 E1 的全部输入。这种"半真半假"比 `unknown` 更坏：unknown 是诚实的，假数是误导。
   所以只给"两个数都缺"的展补，只缺一个的一律跳过。
5. **自动匹配必须人工过一遍，而且要看数字合不合理。** 第一版跑出 7 条，我逐条核对发现
   **2 条是错的**（佛山陶博会 60万/750 = 800 倍；青岛 SINOCES 匹配到了深圳的同名展）。
   两处都不是"分数低所以可疑"，分数分别是 0.88 和 0.88——**相似度分数不校验语义**。
   补两条与名字无关的规则（比值物理区间、标题地名嗅探）之后才降到 8 条全对。
6. **覆盖率的天花板往往不是抓取能力，是数据本身不存在。** 41 个双缺的展，2670 个第三方详情页
   全量匹配下来一个都没命中。继续加源、加并发、放松阈值，都是在给不存在的数据做功。
7. **"能拿到数据的展" ≠ "随机抽样的展"。** 第三方源覆盖的多是大展，每补一批样本分位就上移一次。
   相对档位可以接受这个偏差（它本来就是排序工具），但绝对档位线会单调上移，跨年比较会失真。
