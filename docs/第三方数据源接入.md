# 第三方数据源接入：去展网

E1 可算比值的展卡在 35/94 上不去，官方站点补采这条路已经走完
（见 `docs/E1缺口补采与闸门修复.md`）。这一轮换方向：去第三方会展平台找现成数据。

结果：**35 → 43**，`unknown` **59 → 51**，E1 分位推到 v4。

但代价是引入了一个已知有系统性偏差的数据源。这份文档主要记录**怎么用才不至于把偏差吃进画像**。

---

## 1. 为什么必须成对使用、绝不混源

先看实测偏差。

| 展 | 去展网 | 官网口径 | 偏差 |
|---|---|---|---|
| CMEF 观众 | 150,000（旧页）/ 200,000（详情页） | 200,000+ | 低 0~25% |
| CHINAPLAS 观众 | 250,000 | 310,000+ | **低 19%** |
| CHINAPLAS 展商 | 3,900 | 4,700+ | **低 17%** |

**观众数系统性偏低 20~25%，展商数相对准。**

E1 的唯一输入就是 `观众 / 展商` 这个比值。如果：

```
分子取自去展网（真实 × 0.78）
分母取自官网（真实 × 1.00）
→ 比值 = 真实 × 0.78，凭空偏低 22%
```

而档位就是按比值切的，20% 的偏移足以跨档。

所以规则只有一条，没有例外：

> **只给"两个数都缺"的展补，两个数必须同源同时写入。只缺一个的一律跳过。**

跳过的代价是诚实：`unknown` 明确说"我不知道"。
混源的代价是误导：一个看起来精确、但系统性偏 22% 的比值。

**unknown 是诚实的，假数是误导。**

当前有 10 个展属于"只缺一个"（6 个缺展商、4 个缺观众）。这些展在去展网都能查到互补的那个数，
但一个都没补——就是这条规则在生效。

只探到 200 还不够，得看**字段是不是结构化的**。去展网的详情页把三个数写死在固定标签里：

```html
展览面积：300000 平方米
展商数量：5000 家
观众数量：200000 人
```

15 页试抓，15/15 全命中，这才敢跑全量。

### 2.1 踩到的坑：城市和展期不在同一个标签里

第一版按 `展会地点：` 取城市，全空。原因是标签和值被 HTML 拆开了：

```html
展会地点：</span><address>...<a title="上海展会">上海</a></address>
```

改成从 `<a title="XX展会">` 的 title 里取城市，从 `<time datetime="2027-04-07/2027-04-10">`
取展期，才拿到。**结构化的前提是"你能稳定定位到值的边界"，不是"字段名存在"。**

全量抓完的字段完整度：

| 字段 | 有值 | 覆盖率 |
|---|---|---|
| title / year / area / exhibitors / visitors / start_date | 2670 | 100% |
| city | 2538 | 95.1% |

2670 条全部"三个数齐全"，用时 268 秒（4 并发）。

## 3. 匹配：三个否决规则，每一个都是被真实错配打出来的

第一版匹配出 7 条。我逐条核对官方数据，**2 条是错的**——而且这两条的分数都不低（都是 0.88）。
这件事本身是这轮最重要的收获：

> **相似度分数不校验语义。** 名字越像的两个展，越容易是一个对的东西配到了一个错的东西上。

### 3.1 规则一：城市 / 地名冲突 → 否决

最典型的一次：

| | |
|---|---|
| 我们的展 | `sinoces` 中国国际消费电子博览会，**青岛** |
| 匹配到 | 深圳国际消费电子展览会，**深圳** |
| 分数 | 0.88 |

名字几乎一样，但根本不是同一个展。

漏洞在两个地方：

1. **`city` 字段有 5% 是空的**，空的就躲过了"城市冲突否决"这道检查
2. 去展网给的那个条目城市恰好是空的

所以地理信号必须查**两个独立来源**：

```python
if ec and qc:                          # 来源1：city 字段
    if ec[:2] == qc[:2]: +0.05
    elif 同省: 中立
    else: 否决
if ec:                                  # 来源2：标题里的地名
    qp = place_of(cand["title"])        # "深圳国际消费电子展览会" → "深圳"
    if qp and qp[:2] != ec[:2] and 不同省: 否决
```

`place_of()` 用的是一张 157 项的地名表（中国主要会展城市 + 常见海外举办国）。
它必须在 `norm_name()` **之前**跑——归一化会把括号整个剥掉，
而括号里恰恰常写着举办地（`中国（北京）服务贸易交易会`）。

### 3.2 规则一之补充：同省不等于同城，也不等于不同展

第二次跑，`yiwu-fair`（义乌国际小商品博览会）被错误否决：

```
我们的 city = 义乌
去展网的 city = 浙江     ← 它写的是省，不是市
```

`"义乌" != "浙江"` → 判成城市冲突。这是**假否决**，而假否决比漏判更贵。

修法是加一层省-市映射，但**同省只判中立、不加分**：

- 义乌 / 浙江 → 同省 → 通过（救回 yiwu-fair，比值 67，很健康）
- 广州 / 广东 → 同省 → 通过
- 广州家具展 / 东莞名家具展 → **也是同省**，如果加分就会混起来

所以：城市相同加分 `+0.05`，同省不同市 `±0`，跨省否决。

### 3.3 规则二：观众/展商比超出 4~400 → 否决

第一次跑出来的 `foshan-ceramics`：

```
佛山陶博会    观众 600,000 / 展商 750 = 800 倍
展览面积 300,000 平米
```

面积 30 万平米装 60 万人是物理上不成立的一天（人均 0.5 平米，站着都挤）。
真实情况是**把历届累计人次当成了单届观众**。

这个数的危险在于它长得像"特别好的展"——分子大、比值高，还会把 P75 往上推。

区间边界不是拍的，来自 persona.db 里 35 个真展的分布（归一后 P25=25.4 / P50=40.0 / P75=73.3），
几乎全部落在 5~300，取宽松边界 `[4, 400]`。

跑下来剔除 15 条，全是同类问题：

```
巴西圣保罗游戏展览会     1300000 / 459  = 2832 倍   ← 累计人次
日本游戏展览会            220000 / 390  =  564 倍
日本东京动漫展览会        132557 / 216  =  614 倍
俄罗斯莫斯科纺织机械展      7300 / 5002 =    1 倍   ← 明显解析错位（观众比展商还少）
中国（佛山）陶博会        600000 / 750  =  800 倍
```

### 3.4 规则三：分数 < 0.80 或与第二名分差 < 0.05 → 不自动填

分歧太小的不猜。唯一触发的是 `ccbef`（深圳跨境电商展览会）：
两条候选归一后都是 `深圳跨境电商`——因为 `_GENERIC` 把"全球"也剥掉了，
`深圳跨境电商展览会` 和 `深圳全球跨境电商展览会` 变成同一个字符串。数据不同（15万/2500 vs 10万/1500），
无法判断该取哪条，**不填**。

### 3.5 相似度函数本身的两个补丁

这两条不是否决规则，是修"该匹配的匹配不上"：

**补丁一：末尾单字"展"要剥。**
办展方一半写"XX展览会"一半写"XX展"。只剥整词"展览会"会让两边差一个字符：

```
SIAL西雅国际食品和饮料展览会  →  sial西雅食品和饮料
SIAL西雅国际食品展（上海）    →  sial西雅食品展     ← 差一个"展"
bigram Jaccard = 0.545，卡在 0.80 门槛下
```

只剥末尾（`展$`），不动中间的"展位""展馆"。剥完 → `sial西雅食品` 被 `sial西雅食品和饮料` 包含 → 0.88。

**补丁二：中英混写的名字要拆开比。**

```
我们的：国际门窗幕墙博览会 FENESTRATION BAU CHINA  → 门窗幕墙fenestrationbauchina
去展网：中国国际门窗幕墙展览会                      → 门窗幕墙
```

英文尾巴把中文主体的相似度稀释到 0.192。改成"整体比 + 纯中文字段比，取 max"后升到 1.00。

**补丁三（反面）：包含关系给 0.88，但短串至少 5 个字符。**

放宽包含门槛到 0.45 是为了救 SIAL，结果引入了两条假阳性：

```
"消费电子"(4字) 被 "巴基斯坦消费电子" 包含 → 0.88   ← 青岛的展配到了巴基斯坦的展
"健康产业"(4字) 被 "广州妇幼健康产业" 包含 → 0.88
```

名字剥完通用词只剩 4 个字的，本来就没有足够信息判定同一性。加长度下限后两条都退回真分数。

## 5. 落库：怎么保证不覆盖一手数据

三个机制：

1. **新增 `expo.scale_source` 列**（迁移脚本 `migrate_persona_scale_source.py`，幂等）。
   值 `qufair` 标记来源，`NULL` 表示官网一手。
2. **`scale_source='qufair'` 的展，比值计算时带 `ratio_source="thirdparty"`**，
   进 `expo_persona.note` 供审计。它不参与任何加权，只用来回溯。
3. **写前逐个断言目标列为空**：
   ```python
   cur.execute("SELECT visitor_count, exhibitor_count FROM expo WHERE id=?", (e["id"],))
   v, ex = cur.fetchone()
   assert not v and not ex, "目标列已被填充，拒绝覆盖：%s" % e["slug"]
   assert not sanity(c), "比值不健全：%s %s" % (e["slug"], sanity(c))
   ```
   断言失败的代价是覆盖官网一手数据，不可逆。

另外 `load_persona.py` 有两处会误伤，已修：

- 原来会删掉所有非官方观测 → 加 `AND COALESCE(source_type,'') <> 'thirdparty'`
- `data_status` 只看两份 JSON，第三方补的数被算成 skeleton → 落库后按实际列重算

验证：写库 8 个展 × 3 字段 = 24 条 `thirdparty` 观测；跑 `load_persona.py` 前后快照比对，
**8 个展的 4 个字段零改动**。

## 6. 分位重标定 v3 → v4

n 从 35 涨到 43，`--calibrate` 报最大偏差 **20.0**（阈值 10），必须重标。

```
v3  归一后 P25=25.4 / P50=40.0 / P75=73.3   n=35
v4  归一后 P25=27.4 / P50=60.0 / P75=76.4   n=43
    原始    P25=35.0 / P50=66.7 / P75=81.7
```

P50 涨了 50%，不是抖动。新补的 8 个全是知名大展（进博会、服贸会、高交会、SIAL…），
观众基数天然大。这是**方向性偏差**：

> **"能拿到数据的展" ≠ "随机抽样的展"。**

第三方源覆盖的多是头部展，所以每补一批，分位就往上移一次。相对档位可以接受
（它本来就是排序工具，大展该排前面），但绝对档位线会单调上移，跨年比较会失真。
如果将来要用档位做时间序列，得换固定档位或另找锚定样本。

重标后的档位分布：

```
ample 11 ｜ normal 11 ｜ thin 10 ｜ severe 11 ｜ unknown 51
```

四档各占 25% 左右——四分位定义决定的，正好说明分位线算对了。

## 7. 已知缺陷与不做的事

- **8 个第三方条目的比值是下限估计。** 观众数偏低 20~25%，比值相应偏保守。
  想校正需要同源对照数据，目前只有 CMEF / CHINAPLAS 两个点，不足以标定一个校正因子。
  所以不校正，只在 `RATIO_CALIBRATION["caveat"]` 里写明。
- **不去展网取面积以外的字段。** 展位价格、截止日它也没有，E3 依然是 0%。
- **不做"只缺一个"的补数**，即使源上有。见第 1 节。
- **不把 2670 条全部导入。** 只补我们已有的 94 个展，不做展会发现。
  索引留在 `data/batch4/qufair_index.json` 备查。

## 8. 重跑

```bash
cd expohub-backend

# 1) 抓索引（全量 2670 页，4 并发约 4.5 分钟，断点续爬）
../.venv/Scripts/python.exe scripts/persona/collect_qufair.py --workers 4

# 2) 只出报告，人工核对 fill 行
../.venv/Scripts/python.exe scripts/persona/match_qufair.py
#    看 data/batch4/match_report.csv：score / second / n_veto / veto 四列

# 3) 确认无误再写库
../.venv/Scripts/python.exe scripts/persona/match_qufair.py --apply

# 4) 重算（注意顺序：load 在前，compute 在后）
../.venv/Scripts/python.exe scripts/persona/load_persona.py
../.venv/Scripts/python.exe scripts/persona/compute_persona.py --calibrate
../.venv/Scripts/python.exe scripts/persona/compute_persona.py
```

`--gap` 调大到 0.1 会更保守（更多判歧义），`--min-score` 调高同理。
**但收紧只减少填的数量，不提高准确率**——错配是被否决规则挡掉的，不是被分数门槛挡掉的。
